# Joining GitHub and a project

## Three separate things

- **Discord participation** gives you a place to meet people and discuss interests.
- **Formal society membership** follows the society's regulations and a Board decision.
- **GitHub organization membership** provides an account with the collaboration access approved by the organization owners.

One does not automatically grant the others. Selecting a Discord track does not invite your GitHub account or grant Write access.

## Join the organization

1. Create or use your personal GitHub account and enable two-factor authentication. Keep recovery codes privately.
2. Share your GitHub username privately with a Board member or the designated onboarding coordinator. Do not post personal contact details in an issue.
3. Say whether you are interested in Quant Research, Quant Development, or both. Describe an existing project you want to join, if you know one.
4. An owner checks the request and existing invitations, then sends an ordinary Member invitation if approved.
5. Accept the invitation within seven days. Contact the coordinator if it has expired or you cannot accept it.
6. The administrator assigns `research-01`, `dev-01`, or both after you accept, based on your stated Discord preferences. Track membership coordinates interests; repository permissions are approved separately when you join a project.

The organization base repository permission is Read. Public repositories can be read by everyone. Team descriptions and repository grants will be confirmed by the owners. The existing team slugs are `research-01` and `dev-01`; joining a track is not an administrative role. The `board` roster is maintained separately by leadership.

You can read public repositories and propose a pull request from a fork before you have organization Write access. Ask for access when it is needed for your agreed work; do not request an owner role to contribute code.

## Join an existing project

Read its README, scope, and open issues. Contact the project lead or comment on a suitable task to agree on a first contribution. A short documentation improvement, reproducible baseline, or focused test can be a useful starting point.

When your project involvement is agreed, a maintainer requests only the repository access you need. Membership in the Development track does not automatically grant Write on the website or shared C++ infrastructure. Follow the documented setup, run the checks, and submit a feature-branch or fork-based pull request. Ask early when you are blocked. Maintainers decide when the change is ready to merge.

You can work across both tracks. GitHub team membership and project access are reviewed as responsibilities change, including semester handovers.

## Propose your own project

Use the [project-proposal guide](project-proposals.md). Explain the question, deliverable, initial milestone, proposed lead, interested contributors, and resources needed. Leadership and maintainers will help decide where the work should live and what access is appropriate. A new repository is created only after a separate approval.

See the [contribution guide](../CONTRIBUTING.md) and [Code of Conduct](../CODE_OF_CONDUCT.md) for shared expectations.
